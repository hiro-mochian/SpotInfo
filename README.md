# Spot — GitHub移植準備

身近な「ここ、いいよ」を共有する地図アプリ **Spot** の移植用リポジトリです。2026年9月23日に提供された `Spot_atlas_docs(1).zip` を取り込みました。

> **このリポジトリは、現時点では実行可能なアプリケーション一式ではありません。** 添付資料に含まれる復元ソースとドキュメントを保存した段階です。新サイトはまだ公開しておらず、元サイトも変更していません。

## 移植の方針

投稿、ログイン、本人の投稿の編集・削除、地図検索、日本語・英語の表示を維持して、コード管理と公開環境を移します。閲覧専用サイトへの縮小は行いません。

元の公開サイトは [Spot](https://spotatlas-jettiem7.manus.space/) です。ここに保存したソースは、提供資料によれば公開バンドルから復元された製品差分であり、元プロジェクトの完全なエクスポートではありません。バックエンドの復元内容も、元サーバーの実装と一致することを確認したものではありません。[1]

## 実行可能にするために必要なもの

`package.json`、依存関係のロックファイル、ビルド設定、アプリケーションの起動処理、共通UI部品、`server/_core`、認証処理などが不足しています。この状態で `npm install` や `npm run build` を実行することはできません。

元のログインはManus OAuthに、地図はManusの地図プロキシに依存しています。新しい環境で使う認証方式と地図サービスの接続を確定する必要があります。既存アカウントやログイン状態を自動で引き継げるとは確認できていません。

添付の公開データ3件はすべてゲスト投稿です。ユーザー情報や非公開DBの完全なバックアップは含まれないため、これだけで全データの移行完了とは扱いません。公開直前には最新データと所有者対応の確認が必要です。

## 公開環境

GitHubはコード管理に使用します。GitHub Pages単独ではサーバー側の処理やDBを実行できないため、元の機能を維持するには別の実行基盤が必要です。[2]

候補は、GitHub Pagesで画面を公開し、SupabaseでDBと認証を扱う構成です。所有者以外の編集・削除をDB側で拒否する制御を設定できます。[3] **この候補はまだ採用・接続・構築していません。** 実際のサービス選定と認証方式が決まってから実装します。

## キーと個人情報の扱い

復元された `Map.tsx` に埋め込まれていたキーは取り込み前に除去し、`VITE_MAPS_PROXY_KEY` の参照へ置き換えました。キーの有効性や新しい公開ドメインでの利用可否は未確認です。

`.env`、秘密鍵、依存パッケージ、ビルド生成物はGitに含めません。`.env.example` は値を空にしています。`VITE_` から始まる変数はブラウザ用バンドルに含まれるため、DBの秘密鍵や管理権限キーを設定してはいけません。

## 公開前の検証

不足する基盤を実装した後に、ビルド、地図の表示と検索、ゲスト投稿、ログイン投稿、本人による編集・削除、他人の投稿への変更拒否、所有者IDの偽装拒否を検証します。実データの移行を確認し、公開対象と設定について承認を得てから新しいURLを公開します。
