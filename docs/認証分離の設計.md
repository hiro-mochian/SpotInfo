# Google認証と管理者権限の設計

一般利用者、オーナー、管理者はFirebase AuthenticationのGoogleプロバイダーだけでログインします。ブラウザから送られたメールアドレスや自己申告の役割は権限判断に使いません。

Firestoreルールは署名済みトークンの `firebase.sign_in_provider=google.com` と `email_verified=true` を検査します。投稿の作成と非公開所有者情報の作成は同じバッチで行い、`getAfter` で対応を確認します。旧投稿の所有権取得や、所有者UIDだけの変更は許可しません。

オーナーと管理者には、運営者がFirebase管理APIから `role=owner` または `role=admin` のカスタムクレームを付けます。現在、承認された初期オーナー1名を設定しています。他人の投稿を管理者が直接編集・削除する機能は追加していません。

公開データは `spots`、非公開所有者情報は `spotOwners` に置きます。一般利用者が読み取れるのは自分の所有者情報だけで、管理者クレームがあるGoogleセッションは管理画面に必要な所有者情報を読み取れます。
