# 公開前のログイン設定

現在、Supabaseには投稿データと所有者制御の実装があり、GitHub Pages用の画面もビルドできます。**利用者向けの認証プロバイダーはまだ設定していないため、公開は停止しています。**

元サイトのManusログインを移すことはできません。公開版では新しいアカウントでログインする必要があります。最小構成の候補はGitHubログインです。GitHubアカウントを持たない利用者にもメールで登録させる場合は、別途メール送信サービスを設定する方式を選びます。Supabaseの既定メール送信は原則として組織のメンバー宛てに限定され、一般公開用の代替にはなりません。メール認証を無効化して回避する設定は行っていません。[1]

## GitHubログインで進める場合

これは移行作業用GitHub CLIの認証とは別の設定です。以下の内容を確認して、サイト用のOAuthアプリを登録します。サイトはプロフィールとメールアドレスの読み取りだけを要求し、利用者のリポジトリ操作権限は要求しません。[2]

[GitHubの新規OAuthアプリ登録画面](https://github.com/settings/applications/new)を開き、次の値を入力してください。

| 項目 | 値 |
| --- | --- |
| Application name | `SpotInfo` |
| Homepage URL | `https://hiro-mochian.github.io/SpotInfo/` |
| Application description | `Spot shared atlas sign-in` |
| Authorization callback URL | `https://xscvnppiknkzxelzgfnj.supabase.co/auth/v1/callback` |
| Enable Device Flow | チェックしない |

登録後にClient IDを控え、Generate a new client secretでClient secretを生成します。**Client secretをGitHubのコードやチャットへ貼り付けないでください。**

次に[対象Supabaseプロジェクトの認証プロバイダー設定](https://supabase.com/dashboard/project/xscvnppiknkzxelzgfnj/auth/providers)を開きます。Authentication → Sign In / Providers → GitHubでGitHubを有効にし、Client IDとClient secretを対応する欄へ入力して保存します。

## 設定後の公開

Site URLと許可するリダイレクト先は、すでに `https://hiro-mochian.github.io/SpotInfo/` だけに設定しました。メール確認・MFAなどの既定値は変更していません。

GitHubリポジトリには公開用のProject URLとpublishable keyだけをActions変数として保存しています。OAuthのClient secretはSupabase側にだけ置きます。

設定完了後、担当エージェントが公開前チェックを再実行します。認証プロバイダー設定を確認し、公開内容が了承された段階でPagesを有効にして手動の公開ワークフローを実行します。公開後にブラウザでログイン・ログアウト・本人の投稿編集削除を確認します。設定が存在するだけでは、OAuth往復の実動作確認完了とは扱いません。

## 旧投稿の本人対応

元サイトのID `30001`（セーチェーニ温泉）は旧所有者ID `1` を持っています。新しいユーザーにはまだ割り当てていません。この投稿が誰のものか確認し、その本人が新サイトへログインしてから、旧IDと新しいSupabaseのユーザーIDを対応付けます。対応付け前でも公開閲覧は可能ですが、誰でも編集できる状態にはしません。
